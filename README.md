# AJ Import — сайт с каталогом Encar + Che168

Полный каркас: backend (парсинг + API) и frontend (каталог с фильтрами, карточки авто, заявки).

## Структура
```
backend/   Node.js/Express API + парсеры Encar/Che168 + PostgreSQL
frontend/  React + Vite каталог
```

## Быстрый старт

### 1. База данных
```bash
createdb ajimport
psql ajimport -f backend/src/schema.sql
```

### 2. Backend
```bash
cd backend
cp .env.example .env   # заполнить DATABASE_URL
npm install
npm run sync -- --once # разовая синхронизация (для проверки, что парсер работает)
npm run dev             # API на :4000
```

**Важно:** `npm run dev` в backend поднимает только API-сервер (порт `:4000`) и
сам по себе НИЧЕГО не парсит и не обновляет в БД. `sync.js` (`npm run sync`,
без `--once`) — это отдельный постоянно работающий процесс/воркер: он
планирует задачи по `CRON_SCHEDULE` из `.env` (по умолчанию раз в 3 часа) и
обновляет каталог в фоне. В проде это два независимых процесса (например,
два отдельных сервиса/воркера на Railway) — не путай их и не рассчитывай,
что каталог обновится сам по себе, если запущен только `npm run dev`.

### 3. Frontend
```bash
cd frontend
npm install
npm run dev              # http://localhost:5173
```

## Важное про источники данных

**Encar (Корея)** — рабочий вариант "из коробки": используется полуоткрытый
JSON API, которым пользуется сам сайт encar.com. Требует аккуратного
троттлинга запросов и, при больших объёмах, IP из Кореи (см. `PROXY_URL_KR`).

**Che168 (Китай)** — самая капризная часть. Основной список объявлений
рендерится через JS и защищён от прямого HTTP-скрейпинга. В `che168.js` дан
рабочий каркас на axios+cheerio для точечных случаев, но для полноценного
объёма объявлений в проде понадобится:
1. Резидентские прокси с китайским IP (`PROXY_URL_CN`).
2. Headless-браузер (Playwright) вместо чистого HTTP-запроса — комментарий
   с примером кода уже оставлен внутри файла.

Рекомендую на первом этапе выложить сайт с Encar (полностью рабочий парсинг)
и заглушкой/небольшим списком по Che168, а прокси под Китай подключить
отдельным шагом — так быстрее увидеть первую рабочую версию.

## Деплой
- Backend + PostgreSQL → Railway (как в остальных твоих проектах).
- Frontend → Vercel, с `VITE`-прокси/rewrite на backend API либо через
  переменную окружения с полным URL backend, если понадобится вынести `api.js`
  на абсолютный адрес.
- Синхронизацию (`npm run sync`) можно оставить как отдельный worker-процесс
  на Railway с cron-расписанием (`CRON_SCHEDULE` в `.env`), либо гонять
  разово через Railway cron jobs.

## Дальше по приоритету
1. Заполнить `CHE168_LIST_URLS` в `sync.js` конкретными ссылками по маркам/городам.
2. Словарь брендов China (кит. иероглифы → латиница) для `che168.js`.
3. Калькулятор растаможки (сейчас `price_rub` — заглушка, считается только
   курс валют; логику пошлины/акциза можно добавить отдельным модулем
   `backend/src/customs.js` и дергать его при апсерте машины).
4. Подключить лид-форму к Telegram-боту (как в остальных твоих проектах).
